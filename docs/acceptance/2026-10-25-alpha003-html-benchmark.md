# Alpha003 单文件 HTML 输出与重新对比

日期：2026-10-25。仓库：`fincore_cpp`，分支：现有 `dev`。

## 本轮范围

按用户要求，Python 与 C++ benchmark 各自只生成一个离线 `research.html`。
完整因子、signals、labels 和研究计算仍执行；只把八张研究统计表、参数和运行摘要嵌入报告，停止导出大面板与 CSV/JSON 侧车文件。
库的 CSV/export API 不变。

统一对比入口在每对进程完成后核对 HTML 内的数据，结束后仅保留 Python 报告、C++ 报告与 `comparison.html`。
预热、重复样本和进程日志自动清理；逐对结果、原始时间、CPU 亲和性、峰值内存、环境和输入摘要保存在对比 HTML 内。
进程、结果一致性或单文件输出契约失败会立即停止后续样本，并保留有限失败摘要。
`--skip-run` 只复核保留报告的哈希及最后一对数值，不声称重新检查已删除的中间文件。

新契约为 `alpha003-html-v1`，比较 workload 与八张表的列、顺序、精确字符串/整数、缺失值掩码及有限浮点绝对误差（不超过 `1e-6`）。
NaN 表示为 null，无穷值拒绝。旧 `alpha003-complete-v2` 包含大型 CSV 输出，不能用新加速比追认旧输出工作负载的性能门禁。

## 实现验收

- Release 原生库和 benchmark 构建成功；改动仅在 benchmark、报告模板与测试/文档中。
- 64 文件独立真实运行：两侧各一个 HTML，八表最大绝对差 `1.942890293094024e-16`。
- 64 文件控制器真实验证：同一 CPU 0、单线程，两个预热对和一个测量对均通过；输入摘要前后一致。
- 控制器仅保留三个 HTML，无临时目录；保留对哈希与数值复核通过。
- Python 定向测试 47/47 通过，覆盖报告严格解析/转义/缺失值、写入失败清理、控制器失败停止与清理、CPU 测量及历史 CSV 契约回归。
- 模板内嵌 JavaScript 语法检查通过；浏览器策略不允许本地文件预览，本轮未做渲染后的视觉验收。

## 性能复测

实现验收提交为 `ac7d785f1edb295657247bc83333b54a8d01c772`。该提交的干净源码分别测量 500 文件与全量 5,471 文件。
每个规模两对预热、五对 AB/BA 交替样本，固定同一逻辑 CPU 0、计算库线程数 1；外部 process wall 包含进程启动、计算、报告写入及退出。
中位数与 IQR/median 噪声一起报告；噪声超过 10% 时结果标为 INCONCLUSIVE。

环境：Intel Core i9-13900HX，Windows，MSVC 19.42 Release，Python 3.14.2 / pandas 2.3.3 / NumPy 2.4.1。
Python 参考仓库固定在 `3e9ef205ef2023f92e89fddd1052d46b16429c64`。

| --- | ---: | ---: | ---: | ---: | --- |
| 500 文件 | 6.733809 s | 0.220238 s | 30.5752× | 1.68% / 12.48% | INCONCLUSIVE |
| 全量 5,471 文件 | 46.565666 s | 2.417637 s | 19.2608× | 9.43% / 76.10% | INCONCLUSIVE |

两个批次的数值一致性均通过：各两对预热和五对测量的 workload 与八表全部 PASS。

全部 28 个子进程退出零，亲和性 CPU 0 / mask 1 已核对，线程数配置为 1、动态线程关闭；前后输入摘要一致。
两个批次均保留最后第五对，报告哈希及最后一对的数值复核再次通过；历史对没有重跑。

本轮没有针对噪声重新挑选样本或继续性能优化，不能据此声称稳定的 30× 全量加速。
