## 分母与进度

P126 建立符号清单：路径、完整限定名/签名、模块、公开性、注释状态、适用
契约项、英文/中文页面、审阅状态和例外原因。函数重载逐项记录；配置字段、
枚举值和非函数公共类型不能从分母消失。Doxygen 抽取结果与该清单交叉比对，
避免解析遗漏被统计为“没有需要说明的接口”。

最终范围内的公共符号须 100% 有说明或逐项经过审阅的合理豁免；分别报告
有说明数量、豁免数量、缺失数量及提取遗漏数量，不将豁免包装成已文档化。
明显访问器/单纯别名可复用类型或共同契约；含数值、生命周期或副作用约束的
API 不能以“名称直观”为由豁免。公共 API 的中文解释也适用这一分母。

对 `src`、测试和工具按文件记录“已审阅/需补充/有理由无需补充”，并登记
重要算法和不变量的说明位置。不以注释行数、注释比例或每个函数都写一段
作为质量门槛。代码逻辑简单时，审阅后保留无注释是合理结果。

## 注释轮验收

| 检查 | 通过条件 |
|---|---|
| 范围 | Diff 仅含批准文件的注释；没有第三方、冻结快照和无关改动 |
| C++ 行为 | 编译器感知的词法/预处理检查配合人工审阅确认签名和非注释 token 不变；检查续行、宏及位置敏感使用 |
| 特殊文本 | 保留工具指令、许可证、示例字符串和序列化内容，不采用正则删注释作为唯一证明 |
| Python | 普通注释和 docstring 分开；docstring 轮仅允许明确的文档字符串变化，其余 AST/默认值/装饰器/执行逻辑一致 |
| 契约 | 作者对照实现和已有测试；另一名审阅者核实单位、边界、异常、所有权等适用项，没有凭空保证 |
| 提取 | 新增说明出现在预期 API 页面；参数无错配，重载与类型无遗漏或重复冲突 |
| 回归 | 运行本轮相关已有测试/编译检查；如果 token、源码绑定或生成行为异常，先定位，不降低断言求通过 |
| 双语 | 对应英文和中文说明同步，术语及交叉引用一致 |

新增注释可能改变调试行号和对象文件元数据，因此不要求二进制逐字节相同。
但发现 `__LINE__` 等可观察差异时必须缩小或调整注释位置，并重新审阅。
Python docstring 元数据变化不应被报告成“源码完全未变”。任何超出批准说明
范围的行为差异均使该轮停止验收，进入[问题处理流程](review-findings.md)。

优先使用已有测试和当前提交的 CI 结果，不为了证明注释存在而新增镜像式测试。
仅在文档工具、示例提取或校验器有实际逻辑时安排有区分力的测试。无需重跑
已接受的重型性能批次，不为文档交付重建大规模研究结果。必要的新验证依据是
本轮变化和具体风险，而不是累积测试数量。

## 文档构建与内容验收

| 项目 | 最低通过条件 |
|---|---|
| 环境 | 从干净克隆和独立文档环境成功构建；依赖可重建，核心 CMake 不依赖文档工具 |
| API | 清单与渲染结果一致；至少核验所有公开模块，C++23 签名、模板、重载和默认值正确 |
| 严格构建 | 两语言均执行 Sphinx 严格构建与引用检查（例如 `-n -W --keep-going`）；无未处置告警 |
| 翻译 | 所有必需页面和 API 解释有中文；公开范围的缺译/失效/fuzzy 项为零，标识符等非翻译项单列 |
| 链接 | 站内页面、锚点、下载资源、API 引用无断链；无本机路径或被忽略生成物链接 |
| 外链 | 核实主要安装和依赖链接；临时网络错误单列，真实死链修正；例外逐项记录 |
| 示例 | 双语共用同一代码源；安装后的最小 consumer 可编译运行，常见模块示例按适用已有平台验证 |
| 事实 | API 数量来自同提交清单；平台、功能差异、性能统计与有日期的证据一致 |
| 展示 | 中英文目录、搜索、公式、代码复制、长签名/表格、移动端和键盘访问可用 |
| 产物 | HTML/XML/缓存/大型数据不进入 Git；发布包无敏感信息、意外历史目录或平台禁止的链接文件 |

构建期间可以根据已审阅的精确例外处理外部类型引用，但不得使用全局忽略
warnings、忽略所有未解析 API 或跳过中文来获得绿色结果。每个例外有明确
范围、理由和复查条件；源码中的真实错误不能用文档例外豁免。

示例验证区分“命令经过实际执行”“仅静态核对”和“平台未验证”。当前项目
配置了三平台构建 CI 不等于本次三平台安装教程已经通过。文档工具试点无需
编译全部业务库；消费者及示例验证单独安排，不在 RTD 构建中跑重型业务测试。

## 发布验收

四个组合分别记录，不只截图一个首页：Read the Docs 英文、Read the Docs
中文、GitHub Pages 英文、GitHub Pages 中文。每个组合检查首页、安装页、
一个深层 API 页、语言切换、版本标识、静态资源和搜索；核对它们来自同一
已验证提交。Pages 额外验证仓库子路径，RTD 核对两个语言项目的关联与版本。

语言切换应保留页面与版本；页面确实不存在时显示明确回退说明，不能把错误
语言的内容伪装成译文。若只有 `latest`，菜单不提供不存在的 `stable`。
平台设置未完成时标记“配置待完成”；只有本地 HTML 时标记“可部署产物”，
只有平台构建成功但未访问页面时标记“线上检查待完成”。这些都不是 P133 PASS。

PR 只生成预览，不直接更新公开网站。正式发布的构建和部署分开，失败时保留
上一成功版本，记录如何选择上一提交重新部署。平台发布不是性能验收，不用
重新测量或上传大型 benchmark HTML 来证明文档发布成功。

## 问题、提交与交接

每个小轮完成以下步骤：确认工作区基线与明确路径 → 修改该轮允许内容 →
自检和独立审阅 → 对应验收 → 仅暂存明确文件/已接受 hunks → 提交到现有
`dev` → 记录实际提交和剩余事项。验收失败就在同轮修正，不扩大成未审阅的
功能修复，也不拖到全部模块完成才提交。

轮次记录只需以下必要内容，优先引用 CI 和提交，不堆积可再生日志：

| 字段 | 应记录的值 |
|---|---|
| 范围 | 阶段/子轮、仓库分支、父提交、明确文件和符号/页面范围 |
| 结果 | 检查命令或 CI 链接、实际结果、未执行项、精确例外 |
| 审阅 | 审阅人、关键契约/译文结论、问题登记 ID |
| 交付 | 实际提交哈希；若为发布轮，再记录两平台真实地址、语言和版本 |
| 下一步 | 剩余范围、外部设置阻碍、独立修复项 |

P134 交付最终范围和覆盖摘要、两个语言入口、平台配置/回滚说明、维护责任、
未关闭问题及其影响。允许把无关代码缺陷转交后续独立迭代，但若问题使当前
接口说明无法真实表达或示例不可用，则对应必需文档不能记为通过。禁止以
“问题已登记”替代本迭代必要页面和发布的实际验收。
