## 目标含义

“30 倍”定义为 `S = Python 端到端墙钟耗时中位数 / C++ 对应耗时中位数`，
不是在当前 C++ 上再提高 30 倍。主验收场景为 alpha003 的 500 文件样本与
全量 5,471 文件，两者都须达到 `S >= 30`；`S >= 100` 为分别记录的进取目标。
两者使用同机、同一个逻辑处理器的单核预算、相同数据与完整计算/导出工作量。
未达到门槛不能用内核跑分、多个场景平均值或多核成绩替代。

“整体”指上述完整研究流程。标量、rolling、portfolio、稀疏/稠密面板也要做
代表性测量和回归，不能据 alpha003 宣称所有 API 都提高了 30 倍。

以下仅用已有历史进程耗时说明目标规模，不作为新验收基线：

| 场景 | Python 历史中位数 | C++ 历史中位数 | 历史比值 | 30 倍所需 C++ 时间 | 100 倍所需 C++ 时间 |
|---|---:|---:|---:|---:|---:|
| 500 文件 | 8.444698 s | 0.608239 s | 13.88× | ≤ 0.281490 s | ≤ 0.084447 s |
| 全量 | 67.398449 s | 7.973192 s | 8.45× | ≤ 2.246615 s | ≤ 0.673984 s |

因此最低目标仍要求当前 C++ 全量流程再快约 3.55 倍；100 倍要求约 11.83 倍。
只做局部微优化不构成足够路线，计划包含内部数据布局、计算复用和导出结构调整。
P112 冻结新基线后重新计算绝对时间预算，保留以上历史数据，不回写旧结果。
