## 3. 性能判定

每个正式批次、每个主场景：

`S = median(Python process_wall_seconds) / median(C++ process_wall_seconds)`

- 最低门槛：500与全量在两个有效独立批次中均 `S >= 30`，且该场景每批
  至少80%的配对样本（10对时至少8对）的速度比达到30；不足时标未达标或
  INCONCLUSIVE，不能四舍五入。
  这是有意设置的两道门槛：中位数之比与逐对比值不等价，两项都要检查。
- 进取目标：同样条件将30替换为100。分别列明达成的场景，不能将全量100倍
  泛化到500样本，或将一项100倍替代其他项。
- 30倍最低性能通过仍须满足全部功能、资源、代表性回归和交付门禁。
  100倍未达成时明确保留“未达成/继续探索”，不把它改写为已证明不可能。
- 通用八类benchmark相对P112 C++参考使用版本化的5%回归门禁。先按相同协议
  取得至少10对reference/candidate样本，计算 `R=median(candidate)/median(reference)`。
  对配对索引进行10,000次有放回bootstrap（固定seed=92026），每次重算R，
  取2.5%/97.5%分位形成95%区间：上界≤1.05为PASS，下界>1.05为FAIL，
  其余为INCONCLUSIVE，需要定位噪声/增加预先指定的样本批次，不能视作PASS。
  P111须实现并测试这个判定；现有tools/run_benchmarks.py的
  `max(10%, observed spread)`规则不能直接冒充迭代9门禁。不能用alpha003收益
  抵消另一路径回退。跨平台速度单独报告，不要求复现同一个绝对时间。
- 全量峰值内存遵守需求110%预算；同时报告500/稀疏峰值和分配变化，不能以
  少量样本或内存内核证明完整流程资源达标。
