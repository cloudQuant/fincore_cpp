# Phase 55 Native XIRR Plan

**Goal:** Add `xirr` and the shared conventional-IRR root contract that Phase
54 will reuse for `mwr`.

**Baseline:** `dev` after Phase 53 (oracle pin `4b8f31b`). Python source:
`fincore/performance/returns.py` lines 42–268.

**Files:** `include/fincore/performance/returns.hpp`,
`src/performance/returns.cpp`, `tests/unit/performance_returns_test.cpp`.

## Native API

```cpp
double xirr(const dataframe& cashflows,
            std::string_view amount_column = "cashflow");
```

The frame index is the cashflow date (UTC nanoseconds, the frozen native time
representation); the selected column holds signed amounts (negative =
outflow).

## Contract

```text
NUL check -> require_double_column; every amount must be finite (else error)
aggregate amounts by UTC calendar day (ascending day order)
distinct dates < 2 -> input_error
drop zero daily aggregates
sign transitions after aggregation must be exactly one, else NaN
periods = (day - first_day) / 365
solve using the scaled log-gross NPV:
  log|CF| - period*log(1+r), anchored by its maximum, sign-preserving sum
bracket [log1p(nextafter(-1,0)), log(DBL_MAX)]; endpoints must have opposite
signs (existence certificate), else NaN
bisection to a 1e-15 relative log-rate interval (200-iteration cap)
rate = expm1(root); non-finite -> DBL_MAX; rate <= -1 -> NaN
```

The solver is deterministic bisection on the same scaled objective as the
Python oracle (which uses `brentq`); no unconstrained Newton method and no
small-residual root acceptance. Non-conventional streams return NaN rather
than selecting a tolerance-dependent root.
